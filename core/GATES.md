# Gates: deterministic layer through GDPR compliance mapping (Plan Phases 6-20 + Phases 21-22, Steps 31-100 + Phases 21-22)

OWNS: core/**

Scope: The Universal Memory Object exists as a validated Pydantic model with IDs/versioning, provenance, confidence kept independent of truth_status, and bidirectional supersession -- and it runs with zero LLM or network dependency, proving Step 31's requirement that the Memory OS functions as a deterministic data system before any intelligence is attached. Phase 7 adds a rule-based classifier, the LLMProvider interface, the Claude adapter behind it, an extraction pipeline, and entity resolution -- with the core package still importing no vendor code. Phase 8 adds real, persisted retrieval: a SQLite/FTS5 keyword baseline, a dependency-free vector retriever behind the same Embedder-swap pattern as LLMProvider, temporal validity filtering, one-hop relationship retrieval, and fusion into a single ranked result -- storage stays an adapter exactly like the LLM did. Phase 9 closes Memory OS v0.1: the Context Engine turning ranked results into a budgeted package, memory compression (dedup + stale/low-confidence removal, honest about not summarizing without a provider), reflection that structurally cannot start as a confirmed fact, the first evaluation framework (eight of Step 49's nine dimensions tested, Isolation recorded as a known Phase-13 gap rather than faked), and one integration test walking the complete Step 25/50 cycle end to end. Phase 10 gives memories an evidence graph: a typed RelationshipGraph (derived_from/supports/contradicts/etc.), lineage traversal answering "why does the system believe this" back to original evidence (cycle-safe), a belief-maintenance primitive that dampens a memory's confidence toward uncertain once everything it depends on goes stale, and two of the coexistence rules enforced directly in retrieval: superseded facts stay fully discoverable for their own historical window (Rule F) but rank behind their live replacement by default (Rule G). Phase 11 makes the bitemporal model explicit (event_time/knowledge_time as named accessors over the fields that already carried that meaning, not new duplicate storage), extends temporal queries (valid_now, changed_between, previous_state), adds a ConflictResolver that turns a clear time-ordered contradiction into a state transition, resolve_uncertain for the case where confidence genuinely doesn't decide a winner ("I don't know" as a first-class, normalized-probability result, never a forced pick), and apply_correction for "that's wrong" as an Old->Correction->New chain built on the same supersession machinery as everything else. Phase 12 adds a real RetrievalPlanner (question -> intent -> entities -> plan, not just a memory-type label), a QueryDecomposer that splits compound requests into independently-classified sub-questions, a depth-and-size-limited GraphExpander so entity expansion can never explode, a rule-based intent->retriever strategy table (Step 65 -- explicitly not the learned adaptation the plan itself defers to "eventually"), and RetrievalEngine's default fusion now genuinely includes relationship results alongside keyword/vector, not just as a separate opt-in call. Phase 13 adds real agent memory: an explicit owner_id on every memory, an AccessPolicy (owner has full access; anyone else needs an explicit grant or the "*" wildcard, ADMIN implies every other permission), share_to_scope for an agent contributing a SELECTED private memory upward as a new, lineage-tracked copy (never a mutation of the private original), most_specific for Step 70's "the most specific valid memory should generally win" precedence rule, and RetrievalEngine.retrieve()'s new principal_id parameter enforcing real access filtering (opt-in, so every prior test keeps passing with its default None). This closes Phase 9's one deferred evaluation dimension: Isolation is now a real, passing test, not a documented gap. Phase 14 closes Memory OS v0.5: PatternDetector (Step 71's own X-predicts-success worked example), promote_reflection_to_candidate_procedure (Step 72, still CANDIDATE/UNCERTAIN -- the same discipline Step 48 established for reflections), ProcedureValidator (Step 73's 97/100 example, refusing to promote below min_attempts whatever the rate looks like so far), and build_skill (Step 74) -- which closes Phase 10's other deferred rule: Rule E ("a skill cannot automatically become trusted merely because an LLM generated it") is now enforced structurally, since build_skill raises unless the source procedure is already VALIDATED. One integration test walks the complete EVENT->EPISODE->PATTERN->REFLECTION->PROCEDURE->VALIDATED SKILL chain end to end and checks all seven properties Step 75 names (provenance, confidence, temporal validity, relationships, permissions, scope, evidence) are actually present on the result, including a real private-to-shared governance step via Phase 13's share_to_scope. Phase 15 adds security and memory risk: docs/THREAT_MODEL.md (Step 76) answers the plan's own who-can-do-what questions against the actual code, not an aspirational design, and names its own open gaps rather than assuming them solved; MemoryClass (Step 78) keeps instructions structurally separate from memories, defaulting to INFORMATION; PoisoningGuard (Step 77) flags the plan's own worked example (an untrusted document carrying an imperative instruction) as high risk while the identical content from a user statement is not; the trust ladder (Step 79) enforces evidence-gated, one-level-at-a-time promotion, proven against the plan's own "Level 0 -> Level 5" prohibition; and PolicyEngine (Step 80) answers every store/retrieve/share/reason/instruct/export/delete question through deterministic logic and Phase 13's AccessPolicy, never by calling an LLM. Phase 16 adds identity, privacy, and multi-tenancy: MemoryScope.WORKSPACE completes Step 81's Organization->Workspace->Project->User->Agent->Task hierarchy; tenant_id plus can_access_tenant give every memory a hard tenant wall, checked in RetrievalEngine before principal_id's finer-grained permission check, never crossed regardless of what a permission grant says; docs/POSTGRES_RLS.md specifies Step 82's database-layer half precisely enough to build, honestly scoped as not-yet-executable pending Phase 17's Postgres adapter (SQLiteAdapter's JSON-blob schema has no tenant_id column to filter on yet either); PrivacyLevel/PrivacyCategory (Step 83) let a memory be both a level (PUBLIC..SECRET) and zero or more domain tags (PERSONAL/FINANCIAL/SECURITY/CREDENTIAL/PROPRIETARY/INDUSTRIAL); AuditLog (Step 84) records who/what/when/why/source/result, and PolicyEngine now takes an optional audit_log that every can_* decision is logged against when supplied; and Encryptor (Step 85) is a core Protocol with its first implementation, FernetEncryptor, confined to core/adapters like every other concrete vendor library -- opt-in, not auto-wired into storage. Phase 17 adds production infrastructure against a real local Postgres+pgvector instance, not a mock: PostgresAdapter (Step 86) is a second StorageAdapter with a normalized schema (real tenant_id/owner_id columns), which is what finally makes docs/POSTGRES_RLS.md's design executable -- closing the gap Phase 16 named, proven by a test that issues a raw query bypassing the adapter's own Python code entirely and shows the database itself still blocks it; vector_search (Step 87) and hybrid_search (Step 88) move similarity and fused full-text+vector ranking into single SQL statements instead of retrieval.py's app-level Python fusion; add_relationship/relationships_from/relationships_to plus sync_relationship_graph/load_relationship_graph (Step 89) persist RelationshipGraph's edges, closing that module's own "persisting it is a later phase's job" deferral, with RelationshipGraph itself unchanged; and ObjectStore (Step 90) is a core Protocol with FilesystemObjectStore as its first, content-addressed implementation, giving Modality.FILES/BINARY_OBJECT/etc. memories somewhere to put actual bytes via a new, additive MemoryObject.object_ref field. Phase 18 adds observability and reliability, "here are the numbers" instead of "I think it works": Telemetry (Step 91) is a core Protocol in front of OpenTelemetry, the same core-vs-adapter rule as every other vendor library with no carve-out even for one designed to be a neutral abstraction -- OTelTelemetry (core/adapters) is the only file allowed to import opentelemetry, wired as an opt-in parameter into RetrievalEngine and PolicyEngine exactly like Step 84's audit_log; metrics.py (Step 92) turns Phase 9's pass/fail evaluation dimensions into real numbers -- recall_at_k, precision_at_k, mean_reciprocal_rank, contradiction_rate, staleness_rate, provenance_coverage -- as pure functions with no storage or telemetry dependency of their own; memory_evals/ (Step 93) is a benchmark repo of named ground-truth retrieval scenarios that runs the real engine end to end and reports those metrics as actual numbers, runnable via `python3 -m memory_evals`; FailureInjectingStorageAdapter (Step 94) wraps any StorageAdapter and can be told to fail on demand, proving a failed call never partially reaches the real adapter and that RetrievalEngine propagates a real storage outage rather than silently swallowing it; and backup.py's export/import functions plus adapters/file_backup.py (Step 95) prove genuine portable backup and recovery -- a real test round-trips a backup from a SQLiteAdapter, through a file on disk, into a PostgresAdapter, a different storage technology entirely, with memories and relationships intact. Phase 19 adds universal interoperability, closing docs/THREAT_MODEL.md's own named API gap the same turn the API was built rather than shipping it open: core/api (Step 96) is a real FastAPI app with authentication (api/auth.py's per-key Principal, resolved before any route body runs), rate limiting (api/rate_limit.py's per-principal fixed window), and PolicyEngine consulted non-optionally on every memory-touching request, denying as 404 rather than 403 to avoid confirming a memory's existence to a caller who can't see it -- the tenant wall and access policy Phases 16/13 built are enforced at this boundary too, not just in RetrievalEngine; core/sdk (Step 97) is a synchronous Python client tested against a real live uvicorn server on an ephemeral port, not an in-process shortcut; and core/mcp_server (Step 98) exposes remember/recall/forget as real MCP tools calling directly into the same engine, through the same PolicyEngine gate, denying across tenants exactly like the REST layer does. One real environment fix crossed all three: SQLiteAdapter needed an explicit check_same_thread=False opt-in (a new constructor parameter, default unchanged) because both FastAPI and the MCP server run synchronous handlers in a worker-thread pool, not the thread that constructed the adapter. Phase 20 closes the plan's 100-step arc: core/conformance/storage_adapter.py (Step 99) is a runnable certification suite -- CONFORMANCE_CHECKS, plus a positive control proving a deliberately broken adapter actually fails it -- that both SQLiteAdapter and PostgresAdapter pass identically, closing the plan's own self-flagged gap ("no adapter certification or versioning contract"); docs/ADAPTER_ECOSYSTEM.md catalogs all seven named adapter categories honestly, including naming the existing SKILL.md/server/ Skill as the plan's own intended MCP migration target while deliberately not performing that migration here (a live, separate product's behavior isn't changed inside a documentation-freeze phase); and docs/V1_ARCHITECTURE.md (Step 100) is the 32-section V1 architecture freeze -- one document rather than 32 separate files on purpose, since splitting content this codebase's real 20 phases don't support further would mean padding or fabricating, not specifying -- with memory_os.__version__ == "1.0.0" as the concrete freeze marker, and an explicit closing list of what V1 does not include, carried forward from the plan's own eight self-identified gaps rather than silently dropped. Phase 21 (not one of the plan's original 100 steps -- the highest-priority gap I flagged when first synthesizing the plan, built now on the user's explicit choice) closes that first gap without reopening the freeze: memory_os.profiles' TenantProfile maps industry/application-type/business-type to a default policy bundle (sensitivity/privacy_categories), a new additive MemoryObject.tags field for tenant-specific taxonomy extension kept deliberately separate from the closed, reviewed PrivacyCategory enum, and a RetentionPolicy; memory_os.retention's sweep_expired_memories() marks a tenant's aged-out memories FORGOTTEN, never deletes, per Step 35's own supersession philosophy. apply_profile_defaults() is wired into both api/app.py and mcp_server/server.py identically (explicit value beats profile default beats hardcoded fallback), and memory_os.__version__ moves to "1.1.0" -- additive and backward compatible, every one of the 325 tests passing before this phase still passes unchanged. Phase 22 names GDPR as V1's compliance target (closing gap #2), the choice following from who the platform actually serves (any customer, any region, including the EU): data_subject_rights.py's find/export/erase_data_subject() are Articles 15/17/20 as real callable operations over a new additive MemoryObject.data_subject_ids field, with erase_data_subject() calling StorageAdapter.delete() directly -- a genuinely different operation from Phase 21's retention sweep, which marks memories FORGOTTEN rather than removing them, because Article 17 is GDPR's own deliberate exception to Step 35's "never silently disappears" default; TenantProfile gains a data_residency_region field (Phase 22) that records a residency requirement without claiming to enforce it, since which physical region a database runs in is a deployment decision, not something the Python code running inside it can control; and docs/GDPR_COMPLIANCE.md maps every relevant article to what's real, what's newly closed, and what stays organizational or legal (breach notification runbooks, DPAs, an EU representative, Article 30's processing register, DPIAs) -- never fabricated as solved by code. memory_os.__version__ moves to "1.2.0".
